ZWECK

Kompletter Trainer-I/O-Kanal (Trainer-only) — ohne das Spiel: injector.exe lädt rbbridge.dll in einen beliebigen x64-Prozess (Test: notepad.exe), die DLL startet den Named-Pipe-Server \\.\pipe\rbbattle, pipe_client.py sendet ping/exec und druckt die JSON-Antworten. exec ist im Harness ein bewusster no-op (ok:false, TODO(RE)) — getestet wird der Kanal, nicht die Spielsteuerung.

Seit dem Dual-Mode-Umbau (eine Quelle, zwei Builds) geht der Kanal-Test auch ohne jede Injection: rbbridge_standalone.exe (-DRBBRIDGE_STANDALONE) startet dieselbe Pipe-Server-Logik als normales Konsolen-Programm — Test 0 unten. Der Injection-Test ist Test 1.

▸ INSTALL (BUILD)
  1. 64-bit-Toolchain nötig — Injector UND DLL müssen x64 sein (notepad.exe unter Windows 10/11 x64 ist 64-bit). MinGW-w64: 
    x86_64-w64-mingw32-gcc -O2 -Wall -Wextra -shared -o rbbridge.dll rbbridge\rbbridge.c
x86_64-w64-mingw32-gcc -O2 -Wall -Wextra -DRBBRIDGE_STANDALONE -o rbbridge_standalone.exe rbbridge\rbbridge.c
x86_64-w64-mingw32-gcc -O2 -Wall -Wextra -o injector.exe injector\injector.c
    (MSVC-Alt: cl /nologo /O2 /W3 /LD rbbridge.c /Fe:rbbridge.dll, cl /nologo /O2 /W3 /DRBBRIDGE_STANDALONE rbbridge.c /Fe:rbbridge_standalone.exe und cl /nologo /O2 /W3 injector.c shell32.lib /Fe:injector.exe)
  2. pipe_client.py braucht keinen Build (Python 3.7+, „Add python.exe to PATH“).
